# QQ 群消息审核

[![Tests](https://github.com/JunieXD/astrbot_plugin_qq_message_guard/actions/workflows/test.yml/badge.svg)](https://github.com/JunieXD/astrbot_plugin_qq_message_guard/actions/workflows/test.yml)

支持本地 [Qwen3Guard](https://huggingface.co/Qwen/Qwen3Guard-Gen-4B) 和 [OneJev](https://github.com/OmniJev/OneJev) 审核 QQ 发言。每个群可以分别开启自动撤回、群内 @ 警告、私聊通知和管理员群通知；四个开关相互独立。默认只记录，所有操作开关均关闭。

适用于 **AstrBot 4.26.2～4.x + aiocqhttp / OneBot v11 + NapCat**。模型作为独立 HTTP 服务运行，AstrBot 不加载模型权重。建议先验证模型在自己群里的误报和漏报，再决定是否开启自动操作。

## 安装与第一次使用

1. 在 AstrBot 插件页，通过 Git 仓库安装：`https://github.com/JunieXD/astrbot_plugin_qq_message_guard`。
2. 选择审核服务并填写根地址及模型名。Qwen3Guard 的本机部署见[部署说明](deployment/qwen3guard/README.md)，默认地址 `http://127.0.0.1:8001`，模型名 `Qwen3Guard-Gen-4B-Q4_K_M`。旧 OneJev 服务仍兼容，默认地址 `http://127.0.0.1:8000`、模型名 `jev-latest`。不要在地址末尾附加接口路径。
3. 添加来源群，选择需要审核的类别，开启插件总开关。暂时保持四个操作开关关闭。
4. 如果 AstrBot 开启了群白名单，将来源群加入白名单。插件读取所有送达 AstrBot 的群消息，不需要成员 @ bot。
5. AstrBot 的机器人管理员私聊发送 `/消息审核 状态`、`/消息审核 待复核 群号`，检查实际效果。
6. 确认效果后，再单独开启需要的功能。

Windows 桌面版 AstrBot 通常直接用 `127.0.0.1`；AstrBot 在其他 Docker 容器中时，可按部署网络使用 `http://host.docker.internal:8000` 或同网络服务地址。无需将模型端口公开到互联网。本机 OneJev 无 API Key 时留空。

配置面板使用中文说明，Qwen3Guard 最小示例见 [qwen3guard.example.json](examples/qwen3guard.example.json)，OneJev 完整示例见 [config.example.json](examples/config.example.json)。示例中的群号仅为占位，请替换。

## Qwen3Guard：当前消息直接分类

选择 `qwen3guard` 后，插件使用冻结的官方用户消息审核模板，直接调用 llama.cpp 原生 `/completion`，不经过 OneJev。每条消息一次分类，不等待批量、不定位候选、不读取群聊前文、同作者前文或引用原文。当前消息本身的文字与其静态图片的 OCR 文字参与审核；不把昵称、群名或旧群规混入模型输入。

模型返回 `Safe`（安全）、`Controversial`（有争议）或 `Unsafe`（不安全），以及原生类别。**模型不输出百分比置信度。** 默认“有争议”仅通知管理员，不自动撤回或 @；其中“不当行为＋有争议”只留本地记录，不发通知。“不安全”命中启用类别后按每群开关撤回、@并通知。可关闭有争议审核，或显式开启“有争议时也自动撤回／@”。所有自动操作仍保留完整性、权限、时效、冷却和防重复保护。OneJev 的分数门槛、综合群规、前文设置、词义提示和批量选项对该后端不起作用。

| 默认类别 | Qwen 原生类别 | 边界 |
| --- | --- | --- |
| 敏感话题 | Politically Sensitive Topics | 由模型自身政策判断，并非禁词表 |
| 暴力内容 | Violent | 比旧版“现实暴力威胁”更宽，可能涉及暴力讨论 |
| 不当行为 | Unethical Acts | 包括但不限于仇恨，不能当作旧版“仇恨歧视”的精确同义词 |
| 违法行为 | Non-violent Illegal Acts | 非暴力违法行为，不只诈骗招揽 |
| 色情 | Sexual Content or Sexual Acts | 由模型自身色情类别判断 |

“有争议时只留本地记录的类别”默认包含“不当行为”，可调整或清空。该规则只影响有争议的分类；不安全内容仍按原有开关处理。如果一条消息同时命中其他需要通知的类别，仍按那些类别通知，通知理由只列实际触发通知的类别，本地记录保留全部分类。

另可选择隐私信息、自伤内容、版权侵权、越狱指令，默认关闭。类别过滤不重新提示模型。该模型无法保证执行旧版自定义定义或识别所有敏感谐音；选择仅当前消息也会放弃跨消息消歧。

可关闭“审核消息中的图片”：不会下载图片或运行 OCR，纯图片直接跳过，图文混合只审核文字。

这是**文字模型**，不会查看图片画面。OCR 关闭、失败、截断、无文字或超出图片上限时记为未完整审核，不能自动处罚；已经在可读文字中发现的问题仍可供管理员复核。GIF 继续免审。重复纯静态图片可复用 OCR 和同模型／同类别配置下的分类结果，旧 OneJev 分数不会复用。模型别名、类别或开关变化会隔离缓存；更换权重时也应变更服务别名。

分类格式异常、未知类别、矛盾结果、输入截断、输出未完成、实际模型不符及 HTTP 故障均不会视为安全。每次真实 HTTP 的 token、耗时、完整请求响应和分类保留，缓存命中不虚增统计。查看旧 OneJev 记录仍显示原有评分，新分类记录显示类别及安全判定。

下文有关 0～1 分数、综合群规、上下文与批量初筛的说明仅适用于兼容的 OneJev 后端；操作与记录机制两者共用。

## 四个独立开关

| 每群设置 | 开启后的行为 |
| --- | --- |
| 自动撤回 | 任一审核项达到撤回门槛，覆盖完整、身份和权限核验通过时撤回 |
| 在群内 @ 成员警告 | 任一审核项达到警告门槛，发送真实 @ 消息段和配置的警告文字 |
| 私聊通知管理员 | 向配置的 QQ 接收人合并发送通知 |
| 通知到管理员群 | 向指定管理群合并发送通知，bot 必须已加入该群 |

管理员群不能与来源群相同，且不用加入审核群列表。通知默认不重复转发可疑原文，仅说明来源群、成员 QQ、发言时间及处理情况，避免再次传播相关内容。默认每个来源群最多每分钟发一批；私聊与群通知可同时开启。

**OneJev 的管理员通知与本地复核分开判定。** 默认任一审核项达到通知门槛0.80即可通知，达到0.55只保存为本地复核，撤回与@各自默认0.90。所有处理只按类别分数判断，没有额外作者意图门槛；敏感话题或色情内容不会因在举报、劝阻或引用中出现而豁免。通知仍需开启对应开关。GIF及其他动态图按规则免审；附带的文字和静态图片仍继续审核。图片下载失败、模型超时、队列满及离线旧消息只留在日志和状态，不单独往管理群发消息；已发现文本风险但附图不完整时可通知人工复核，仍禁止自动处罚。通知优先显示群名片和QQ号，包含北京时间（精确到秒）、命中类别及模型评分、处理状态，不复述原消息。

Qwen3Guard 通知示例（OneJev 显示其模型评分）：

```text
🛡️ 鼠群 · 审核提醒

成员群名片（123456789）
10月14日 10:30:13
敏感话题 · 不安全 · 已撤回
```

多个命中类别放在同一行，多个记录用空行分隔。未撤回时显示“未撤回”；已提醒但未撤回显示“未撤回（已提醒）”；处理异常或结果不明显示“处理结果待核对”。

发送前重连或暂缓时，确认尚未发出的通知会在连接恢复和通知间隔结束后继续发送；已提交过的渠道不会重复发送。各来源群公平提取待通知记录，一个群的通知积压不会挡住其他群。发送结果不明仍需人工核对。

开启撤回和警告时，顺序为**撤回 → 警告**。只有警告开启时也能单独警告。默认同一来源群的同一成员每小时最多 @ 警告一次，对每个管理员通知渠道也最多提醒一次；持续违规仍逐条审核，符合条件时继续撤回。每群每小时最多 10 次 @ 警告。撤回与提醒使用独立账号额度，互不挤占；提醒冷却跨重载保留，从首次实际发送计时，重复违规不延长。群主和管理员默认免审，不调用模型、不发送审核通知；可在每群设置中关闭免审，关闭后仍不会自动撤回或 @ 群主和管理员。未知身份不会被当作管理员豁免。

“同成员管理员通知冷却分钟数”可设为 **0**，表示同一成员再次出现新风险也继续通知，之前保存的成员冷却不再阻拦。此时每批最多8条风险记录，同一成员的多条也会逐条展示；超过的留到下一批。仍按来源群通知间隔（默认每分钟最多一批）、账号发送额度与同一记录防重复机制控制。此设置不改变群内 @ 的一小时冷却。

警告模板由你填写，bot 自动在前面 @ 成员。可用 `{群号}`、`{QQ号}`、`{审核项}`；普通花括号写成 `{{`、`}}`。不支持任意代码、字段访问或格式表达式。

## OneJev 独立审核类别

默认采用sub2api式独立分类：每个类别明确“违规行为”和“正常例外”，分别返回0～1分数。一次HTTP请求批量提交所有类别，任何一个类别达标都可进入对应处理；不计算含糊的综合总分。通知只显示达到通知门槛的具体类别及各自分数，按分数从高到低列出，最多三项。“置信度”行使用模型的类别评分，不是经校准的现实违规概率。

默认开启5类：敏感话题、色情、诈骗与违法招揽、暴力威胁、仇恨歧视。色情已包含未成年人性化内容，默认不再重复审核“未成年人色情”。隐私泄露、普通辱骂、商业推广、粗俗性玩笑等保留为可选群规项目，可自行添加，每项独立设置门槛。

保留sub2api的13个类别键及原有细分项。“违法帮助”旧配置名自动解释为“诈骗与违法招揽”，底层键仍是`illicit`，旧记录可正常查看。更新不替其他使用者删除已有自定义项目；想采用精简方案可在配置中只保留这五项。旧`intent_enabled`、`intent_confidence`配置不再生效，也不再出现在配置页面。

| 默认项目 | 违规内容 | 正常边界 |
| --- | --- | --- |
| 敏感话题 | 提及、影射政治敏感事件或邪教组织，含谐音、拼音、暗语；举报、劝阻和实际引用中的内容也计入 | 普通政策、旅游地名、历史常识；没有具体敏感内容的泛泛提醒；仅别人的背景命中 |
| 色情 | 色情资源、露骨性内容、未成年人性化表达（不要求露骨） | 普通恋爱、健康教育、未成年人保护，没有色情或性化内容 |
| 诈骗与违法招揽 | 骗钱招揽、犯罪交易、犯罪操作帮助 | 正规收费服务、普通招生讨论、不提供犯罪操作的防骗和法律咨询 |
| 暴力威胁 | 可信的现实伤害威胁或暴力鼓动 | 抽象比喻、普通游戏影视及安全科普 |
| 仇恨歧视 | 针对身份群体的仇恨、非人化贬低或暴力煽动 | 普通学校、招生政策或具体行为评价 |

完整正反定义集中在[类别定义](qq_message_guard/categories.py)。自伤相关细分类默认未启用；其中“自伤意图”即使高分也只供管理员复核，不自动撤回或@处罚。

保留“群规”“诈骗与隐私”“威胁与攻击”三个旧类别以兼容现有配置。默认不选综合“群规”项；只有明确选了它，配置中的旧群规文字才参加模型判断。纯独立分类会移除模型输入中的泛化群规，避免其污染各类别。更新不自动覆盖其他使用者的已保存项目。

默认本地复核门槛0.55、通知门槛0.80、撤回和@门槛0.90。**这些是可调整的起始值，分数不是已经验证的现实违规概率或严重程度。** 模型可能误判或漏判，仍应结合群语境人工复核。人工标记不会自动训练模型。

支持文字、静态图片、OCR及条数缓存中的引用。不会打开网页链接，不识别语音、不抽取视频、不下载群文件、不展开合并转发；GIF及其他动态图主动排除。缺失静态图片、超长文本、静态图片数量超限、引用缺失等均标记覆盖不完整，不自动撤回或@。

### 批量文字初筛

默认开启，可在“批量初筛”中关闭以恢复逐条审核。普通完整文字按群合并，**最多16条新消息或从第一条起等8秒**；模型忙时继续合并尚未领取的新消息，不产生大量固定小批任务。仅1条时直接细审。默认前10条作为重叠背景，并补齐穿插的已细审消息、引用与同作者前文；背景不重复计入新违规。不同账号、来源群、连接和配置的消息不合并。

每批按配置的独立类别判断是否存在需要继续审核的发言；默认初筛门槛0.30。命中时按相关类别定位候选，再用原来的**逐条全部类别**确认，最终通知、撤回和@门槛不变。小批次或定位问题过多时直接细审，不截断类别。初筛、定位和每条细审各自交回公平队列，避免一批连续占用模型；每阶段等待最多按排队设置约束，自动操作仍按原始发言时间计算120秒保护窗口，不因重新排队延长。只凭批量分数不发送通知或处罚。已知风险词、同作者风险词承接、图片、超长文字、解析缺失和综合“群规”项直接走原来的细审。

默认关闭未命中消息的随机抽查，让普通聊天批量初筛后结束，减少额外调用；可按需开启，抽中的消息仍进行完整细审并保留结果。可调每批2～20条、等待1～30秒、重叠0～24条、初筛门槛0.01～0.50、抽查0～100%。若某审核项的本地复核门槛更低，初筛自动取较低值。初筛门槛是保守的继续审核门槛，不是违规概率、严重程度或处罚门槛；不要套用0.80/0.90。更多类别、定位、抽查都可能增加计算，实际节省请看状态中的**初筛、定位、细审实际调用次数**。初筛未命中记录明确标注“未逐条细审”，不伪造单条低分。

所有批量请求响应独立保存并关联每条消息，实际HTTP仅计一次统计；`export_case.py`会一并导出关联的批量记录和调用。正常初筛默认14天，可疑批次、细审或抽查发现风险及人工确认违规的关联批次默认60天。图片和未解析附件不会因文字初筛未命中而跳过。引用撤回、配置变化、超时、重载中断或结果缺失记为未完整审核，不当安全；HTTP413/422输入拒绝会回退逐条，服务故障不立即重试。

### 调度与重复表情缓存

图片不再无条件优先。调度结合各阶段剩余排队时间、原始发言的操作期限和近期实际推理耗时，风险内容有有限的优先权，等待较久的文字批次也能先处理。不同群继续轮流获得处理机会。每批最多16条、最多4000字，消息少时最多等待8秒；上述数量与等待时间均可配置。消息的90秒队列时效和120秒自动操作时效保持独立。

GIF按文件内容识别，仅读取到GIF头就停止下载，不调用OCR或模型；其他动态图同样免审。GIF附带的文字和静态附件仍继续审核，GIF不占静态图片名额。纯GIF记为“按规则免审”，不记成“安全”或“处理失败”。静态图片支持6400万像素以内的普通大图，JPEG优先在解码阶段缩小；更大的图片继续保留覆盖缺失保护。

“表情图片缓存”默认开启，结果缓存24小时、最多256项，可配置1～168小时、16～2048项。重复图片的缩放结果按原始字节哈希保存在最多32MiB/128项的内存缓存，OCR与纯图片审核结果在本地SQLite中有期限地保存。签名URL变化不等于图片变化，不使用图片外观近似匹配。图片缩放参数、OCR字数预算、审核类别或定义、模型服务与密钥等变化会在相应缓存键中体现。

无附文、无引用、没有缺失的**单张静态图片**，在没有已知同作者风险承接且未启用综合“群规”时，按图片本身及其OCR独立审核。该模式不使用前文或发送时间，明确记录为 `image_content`，因此同一图片的完整分数可以复用。带附文、引用、多张图片或需要上下文时继续正常审核，仍可复用OCR。相同图片在不同群不复用最终审核分数。缓存不会复制旧的处罚动作：每条新消息继续按当前门槛、权限、时效、原文身份与冷却条件独立处理。

缓存命中单独记录来源编号与复用次数，不虚增HTTP调用或token统计。来源被人工标记后清除相关缓存，并取消依赖它的待执行通知、撤回和警告；已完成的操作不能撤销。查看缓存结果可追溯原始请求响应，来源记录过期后不再复用。别名模型在服务端原地更新时，若模型名未变化，更新后应关闭缓存，待旧缓存到期后再开启。

### 批量与并行的边界

插件使用同一次请求分享上下文，定义不在公共前缀重复粘贴。当前本机CPU/llama.cpp后端会锁定模型并串行计算答案分支，多发HTTP请求也排队；没有启用人为的并发请求。真正的分支并行由OneJev的PyTorch批处理后端及硬件决定，插件不会擅自改变模型部署。

当前默认细审5类，不再计算作者意图分支；类别数量仍直接影响本机串行推理耗时；批量初筛和候选定位也各有计算成本。默认请求超时90秒，包含服务端等待；队列时效90秒、操作时效120秒仍独立约束。活跃群可能积压，过期或未完成审核只留存，不补发陈旧处罚。模型返回的实际token、各类别分数、完整请求响应均保留在原有审核记录中。

## OneJev 上下文与词义

通常保持默认即可：**群内前 24 条＋当前成员前 6 条＋被引用消息**，去重后按接收顺序提供。没有五分钟或其他时间过滤；背景附北京时间，帮助判断较早的话题。每条背景最多保留 500 字，背景正文默认最多 4000 字，超过时优先保留引用和较新的消息。条数与字数可以在“更多设置”调整。

每群默认持久化缓存最近 512 条，重载后仍可使用。引用和同作者前文只能从该缓存中选取；超过条数容量或普通记录保留期限的内容可能不可用。不向 QQ 补拉历史。忽略名单成员仍可提供背景，但不接受当前消息审核；bot 自己的消息忽略。撤回通知会移除对应缓存，引用原文已撤回时不自动处罚。

内置一个小型词义表，解释实验涉及的少量政治事件拼音、近音写法和粗俗性俚语。可在“补充词义与常见写法”添加自己群里的缩写和表达，自动处理全角、大小写、零宽字符和空白。它提供词义与**复核候选**，不会将普通地名或所有政治讨论直接判违规；该群真正禁止什么仍需写明群规。

“长期保存未完成的词义候选”是每群独立开关：只在模型未完成时帮助延长本地留存，不作违规结论。完整审核的结果、通知和处罚全部由模型分数决定；不单凭词库或正则命中撤回、警告或通知。词义表仍帮助解释缩写，已知候选可优先进入细审，但模型没有确认时不能处罚。

背景仅帮助理解当前内容，实际引用明确并入本次发布正文，按类别定义审核。没有另一次“参与／举报／制止”分类，也没有意图置信度配置。旧记录中的意图字段可作为历史证据保留，但不会影响新版处理。权限、完整覆盖、时效、重连与人工标记保护继续有效。

敏感话题与色情按内容审核，不能通过加上“别说”“举报”等措辞免除其中实际出现的禁止内容；泛泛提醒和只有别人前文包含时不自动算当前违规。已有自定义群规不被升级覆盖；纯独立分类的具体定义以审核项目为准。普通警告不复述原文，警告模板也会检查是否重复词义候选，命中时取消发送并记录原因。

## 图片文字提取

“本机提取图片文字”默认开启。Qwen3Guard 只接收 OCR 文字；OneJev 同时接收 OCR 文字与原图。结果、耗时和使用的本机引擎保存在审核详情，不上传到第三方 OCR 服务。下面关于继续识图的说明仅适用于 OneJev。

- Windows 使用系统自带的中文 OCR，需要安装中文 OCR 语言包；无需额外 Python 推理依赖。
- Linux / macOS 使用本机 Tesseract，需要安装 `chi_sim` 和 `eng` 语言包。Debian / Ubuntu 可安装 `tesseract-ocr tesseract-ocr-chi-sim tesseract-ocr-eng`。
- 无可用引擎、提取失败、超时或结果过长时，原图仍继续提交模型，但记录覆盖不完整，阻止自动操作。超时或重载会停止插件自己启动的 OCR 子进程。
- 可关闭 OCR，仅用原有模型识图。没有识别出文字不等于图片安全，仍然会审核原图。

图片实验目前只验证受控文字图片和正常图片；复杂表情包、低清截图以及 OCR 拼写错误仍可能影响效果。

## 查看与复核

仅 **AstrBot 的机器人管理员名单**具有命令权限；来源群管理员身份本身不授予这些命令权限。其他人不会收到审核详情。

```text
/消息审核 状态
/消息审核 待复核 [群号]
/消息审核 最近 [群号]
/消息审核 查看 编号
/消息审核 标记 编号 误判
/消息审核 标记 编号 违规
/消息审核 撤回 编号
/消息审核 恢复 群号
```

`qmod` 是命令别名。编号可带 `#`。标记只保存人工判定，不新增处罚；误判会取消尚未提交的自动操作。手动撤回也会核验实际消息、权限、账号、配置版本和时效，需要私聊负责该消息的 bot。

“恢复”表示管理员已经核对了暂停原因，重新核验在线状态和 bot 管理权限后解除本插件暂停。已提交的旧请求永不自动重发；如果既有共享协调器也暂停了账号，需要在其所属插件中处理。外部管理员已施加的禁言不受本插件影响，首版不提供禁言或踢人。

## 审核证据图片

在“审核证据图片”中开启“管理员通知附上证据图”，通知会附每名成员的一张首页预览；通知中的 `#编号` 和图片内的编号均可用于私聊 `/消息审核 查看 编号`。查看指令默认返回图片，最多4页。图片包括当前发言、实际引用和默认3条前文；时间、成员和编号保持清晰，正文使用你配置的彩色横线。此排版处理不保证平台允许发送，也不证明平台无法识别。

| 配置 | 默认 | 含义 |
| --- | --- | --- |
| 管理员通知附上证据图 | 关闭 | 私聊通知与管理群通知均适用，现有提醒冷却保持有效 |
| 查看指令回复证据图 | 开启 | 关闭时仅返回定位与审核信息，始终不直接回复原文 |
| 文字横线粗细 | 6像素 | 0～10，0不画线；本地清晰图片不画线 |
| 图片展示几条前文 | 3条 | 0～5，实际引用另外展示；前文每条节选160字 |
| 本机中文字体文件 | 自动 | Windows优先微软雅黑，Linux优先Noto CJK；可填写本机字体完整路径 |

不需要浏览器、模型调用或联网获取头像。图片用本地Pillow渲染；原文页面采用HTML/CSS。Linux没有中文字体时可安装 `fonts-noto-cjk` 或填写已有中文字体路径。字体缺失或图片生成失败时仅发送定位信息，原文不会作为文字回退。QQ已提交但失败或结果不明的请求不会自动再次发送；结果不明仍会暂停账号操作。

命中复核的记录会在撤回前写入 `evidence/编号-source.json` 和 `evidence/编号-local.html`，文字与已保存的审核JPEG随后不依赖QQ原消息仍然存在。归档失败阻止新的自动撤回请求；自动撤回仍受原有权限、完整覆盖与时效保护。截图在通知或查看时生成，不需要等待截图完成才能撤回。

本地页面可直接双击打开，展示收到时留存的原文、引用、上下文和审核图片；它不是公开网页，不会向QQ发送本地原文页面。生成的 `编号-clear-页码.png` 为清晰版，`编号-notice-页码.png` 为QQ发送版。原始附件图片不随通知转发，证据图只展示附件数量与已识别的OCR文字。OCR可能有误。

收到的正文另外最多留存20000字，模型审核仍按原有文字预算执行；图片展示当前正文开头最多4000字和每张图片OCR开头最多800字，超过4页会明确提示未展示全部内容。引用与前文仍受接收时的缓存字数限制。旧记录只能按旧版已有留存范围生成，无法恢复已经截断或未下载的内容。所有证据文件随所属记录的期限清理，查看图片不会延长保留时间。

## 记录、日志和留存

数据保存在 AstrBot 的 `data/plugin_data/astrbot_plugin_qq_message_guard/`，与插件源代码分离，更新插件不会清空记录。

| 内容 | 默认保留 |
| --- | --- |
| 普通审核、未完成审核 | 最后更新后 14 天 |
| 模型命中可疑、人工确认违规、操作结果不明 | 最后更新后 60 天 |
| 人工确认误判 | 改用普通记录期限 |
| 审核后的压缩图片、证据JSON/HTML与PNG | 随所属记录的期限清理 |
| 常规运行日志 / 可疑事件日志 | 按北京时间日期分别保留约 14 / 60 天 |

以上期限都可在高级配置调整。详细记录在 `state.sqlite3`，包含当前文字、已使用的背景、实际 HTTP 审核输入与问题、规则和门槛快照、模型原始有效响应及诊断字段、实际模型名称、输入/输出 token、耗时、覆盖缺失、人工判定和操作提交结果。过期的图片下载 URL 不长期保留；审核使用的 JPEG 保存为本地证据，HTTP 请求里的图片内容不重复保存成大段 base64。

`logs/events-日期-分段.jsonl` 保存普通运行事件，`logs/risk-日期-分段.jsonl` 保存当时命中的可疑事件。每行一个 JSON；达到默认 10 MB 新开分段，定期删除过期日期的文件。日志脱敏传输地址和密钥，详细正文以数据库为准。即使后续人工改判，已经写入的可疑事件日志仍按可疑日志期限保留，不重新改写历史日志。未完成审核但当前内容命中复核词库的记录也按可疑期限保存。

可导出单条详情，不调用任何网络或 QQ 接口：

```sh
python tools/export_case.py --db /path/to/state.sqlite3 --id 12 --out /private/path/case-12.json
```

Windows 下检查正在运行的 SQLite 数据库，应使用 Windows Python 和 Windows 文件路径，避免跨 WSL 的 WAL 文件访问问题。导出包含群聊隐私，请保存在自己的数据目录。仓库只包含构造的测试样例，不上传真实群聊、图片、密钥或运行日志。

## 工程保护

- 事件回调只解析、保存和入队。模型、群内操作、通知各有独立后台任务，慢操作不会占住审核任务。
- 模型请求默认串行；有界队列、按来源群公平取消息、队列时效、故障冷却。满队列或服务出错记为“未完整审核”，不当成安全结果。
- 只处理在线期间新收到的消息，不拉取离线历史。启动和连接变化时记录本地连接边界，时间早于该边界的旧消息不进入模型审核；重载前未完成的任务不恢复，不补发旧处罚。时间来自QQ秒级事件，不能精确区分同一秒内的断线与新消息。
- 状态命令显示当前排队条数、最早等待时间和平均模型耗时。CPU 单 slot 下，带背景的多类别审核通常需要十几秒，活跃群可能积压；过期消息保存为未完整审核，不延后补发旧处罚。同一次 HTTP 的多个问题仍有推理成本，不代表性能无损。
- 单条输入过大或被 OneJev 拒绝（HTTP 413/422）只影响这条审核，不触发所有群的故障冷却；超时和服务故障仍会进入冷却。
- 相同事件持久化去重；记录编号不复用。变更配置或重载后不补发旧处罚。
- 撤回前核对账号、连接、消息时间、群、发送者及内容指纹，并重新查询 bot 和目标成员的角色。
- 成员自行撤回、权限变化、连接改变、离线、过期、人工改判都可取消未提交操作。
- SQLite 持久化写入意图和账号限额。网络超时、缺失发送回执或重载发现未确认提交时记为结果不明，暂停账号操作，不盲目重试。
- 默认每账号每小时最多撤回 180 次、发送提醒 30 次，QQ 查询最多 600 次。达到限额仍保存审核记录，不无上限操作；失败与结果不明的提交也计入次数。
- 撤回前随机等待 0～0.3 秒，撤回完成后到下一操作默认间隔 0.2～0.6 秒，紧随的 @ 警告不重复前置等待；提醒后的账号间隔仍为 2～5 秒。共享排队、权限查询和网络耗时可能增加实际等待。
- 管理员通知等待本条自动操作结束后发送，默认每来源群最多每分钟一批、每批最多 8 位不同成员；重复违规成员在通知冷却期内不刷屏，未展示的成员留待后续批次。断线恢复缓冲默认为 30 秒，旧连接消息不补发处罚。上述参数均在高级配置中调整。
- 与已加载的 QQ 加群审核/群清理共享协调器兼容；没有协调器时只约束本插件，状态命令明确显示。首版不负责其他插件的查询额度。
- 日志写入失败或数据盘剩余不足 256 MiB 时停止自动处理。过期图片删除失败会保留清理任务，后续重试，不因此重复处罚。

随机操作延迟可配置，普通文字初筛会等待最多配置的合并时间；模型计算不额外加随机等待。随机等待不能保证避免 QQ 风控。插件收到事件时 QQ 已经收到消息，撤回也不能保证防止封群；它的作用是降低继续传播和群内管理成本。
